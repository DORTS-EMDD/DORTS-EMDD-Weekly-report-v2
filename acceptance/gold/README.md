# 週報取捨規則與標準答案（召回測試標準答案）

本目錄保存召回測試的標準答案。標準答案只用於離線評分（`scripts/recall_score.py`），
不是 production 的決策依據；正式判定仍由各 owner（Classifier、Reportability 等）依
`docs/ARCHITECTURE_CONTRACT.md` 負責。

## 取捨原則（使用者決定 2026-11-19，契約 §A.58）

以「對臺北捷運局的參考價值」評星：

| 星等 | 判定 |
|---|---|
| ★★★ 以上 | 全收，依分類放入對應章節 |
| ★★ | 收，但只能在「營運動態」或「事故及安全事件」章節 |
| ★ | 不收 |

## 判定依據（不收或限制的情形）

以下規則已寫入契約與提示詞，標準答案依同一規則評定：

1. **專案步驟不收**（RC-63、RC-67 D1）：動土、施工進度、軌道或設備安裝、通車前或試運轉測試、驗收測試、
   新交付車輛進入客運服務前的界限、相容、型式或認證測試、經費或預算申請與決定、成本增加、通車日期的
   變更或預測（延期、新目標日期）。實際通車屬營運動態。在已營運路線上試行或部署一項新技術仍是技術新知。
2. **演練不收**（RC-67 D2）：演練、訓練、預演（含消防、疏散、救援演練），除非來源另報導一件真正的事故。
3. **路口碰撞只收出軌**（RC-70）：電車或輕軌與汽車、卡車、巴士、行人等道路使用者的碰撞，只有來源報導
   列車出軌才收；只有受傷、死亡、損壞、停駛或警方調查都不收。營運者因此採取的軌道安全措施另依其他
   價值路徑判斷。
4. **人為闖入軌道不收**（RC-70）：有人被列車撞擊或進入軌道（闖入、自殺或企圖自殺、從月臺跌落或跳下），
   即使有死傷或停駛也不收；只有來源明載原因在軌道系統本身（號誌或列車控制、月臺門或車門故障等設備
   失效，或司機員、行控、站務的操作失誤）才收，不得推測原因。
5. **非運輸服務不收**（RC-63、RC-66）：車站或車上的非運輸設施或服務（如站內診療亭、車上非運輸服務）
   不是營運動態，也不是技術新知。
6. **天候下照常營運不收**（RC-77）：沒有服務變更、沒有事故、沒有技術內容的日常營運報導（如惡劣天候下
   照常營運）。停駛、減班或改變服務、事故、安全措施仍依原價值路徑判斷。

另依既有規則：獎項與排名、視察與發言、無新發生事項的專題或背景文章（RC-20、RC-25、RC-27）不收；
一般治安、醫療或個人事件只造成短暫局部服務調整者不收（RC-10）。

## 比對方式

```text
python -m scripts.recall_score acceptance/gold/recall_v1.json <selection_audit.json 或召回測試 job log> [...]
```

* 一個標準答案群組＝一則加上 `merge_into` 指向它的重複則。某次執行的已收錄事件只要有成員候選的標題
  等於群組內任一則的 `title`／`aliases`，或包含某組 `keywords`（同組全部出現，不分大小寫），即視為該群組。
* 每個群組判為 CORRECT、MISSED（應收未收）、WRONG_SECTION（收了但章節不符）或 FALSE_INCLUSION（不應收卻收）；
  收錄準確度＝CORRECT／該期群組數。同一群組被收成多則事件時，多出的件數計為重複。
* 未收時列出該群組標題在本次執行停在哪一階段（或 NOT_A_CANDIDATE）；不在標準答案內的已收錄事件列為 NEW，
  供人工補標。
* 章節取自 ReportService 的 `FORMAL_REPORT_SECTIONS`；此工具只觀測，不參與任何決策。
